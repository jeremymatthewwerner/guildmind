## 1. What this checkpoint establishes

This checkpoint turns several Stage 1 requirements into executable code and contract-level tests. It is evidence that the intended container invocation and failure semantics can be inspected and exercised during development. It is **not** evidence that Guildmind is ready to execute external repositories or arbitrary model-generated commands.

The checkpoint covers six bounded areas:

1. a container sandbox contract that declares the required worker and evaluator restrictions;
2. a disposable, image-owned two-phase evaluator path that keeps candidate code and the sealed oracle/result producer in disjoint containers; and
3. guarded, existing-only recovery that converts an interrupted nonterminal local run into one explicit terminal record rather than leaving it silently in flight; and
4. a read-only, bounded ledger/CAS audit that verifies committed bytes and typed recursive relationships before classifying filesystem orphans; and
5. atomic no-replace CAS publication plus a cooperative state-wide maintenance lease for supported runtime mutation; and
6. an explicit resumable orphan-quarantine protocol with fresh authorization,
   deterministic evidence records, and forward-only reconciliation.

Evaluator v2 closes the previously demonstrated shared-interpreter defect for Fixture 001. The candidate phase mounts only the patched workspace and a canonical expected-value-free challenge. Its stdout is untrusted data. A fresh scorer mounts only that response, the challenge, and a sealed oracle; it never imports candidate code. Fixture loading now freezes the manifest, source tree, visible and hidden tests, and canonical oracle before model dispatch; the completion binds that frozen task/source identity. Exact bounded candidate and scorer stdout survive as content-addressed evidence. The checked-in `unittest` monkeypatch, direct grader-path probe, completion-marker forgery, and empty-response attack are now rejected in the development smoke.

The authoritative Stage 1 gate remains open. Docker Desktop on this Mac uses a rootful daemon inside an ARM Linux virtual machine, not the dedicated rootless x86_64 Linux environment required by [ADR 0003](../decisions/0003-sandbox-and-evaluator-boundary.md). The new [`python-call-v1` boundary](../decisions/0004-two-phase-python-call-evaluator.md) covers only bounded JSON-callable micro-fixtures, not arbitrary pytest or repository commands. A strict 19-case [adversarial corpus](../adversarial-corpus.md) covers nine pre-application unsafe shapes plus functional controls, the known boundary attacks, timeout, output exhaustion, and OOM in development. One fixed probe gives repeated development evidence for OOM, PID, and writable-byte enforcement; another now gives three repeated candidate/scorer observations for high-entropy planted secrets, mount/environment separation, credentials, routes, DNS/TCP/Unix sockets, privileged sockets, source integrity, and cleanup. These cases still require reference-host repetition, the containment suite does not yet cover a general worker dispatcher, and only OOM has a corresponding typed evaluator outcome. Eleven real-process `SIGKILL` cases cover five post-commit persistence prefixes, four pre-commit rollback points, and the runner's model/evaluator in-flight boundaries. Nine Darwin CAS kills cover root, `sha256`, and shard `mkdir` after creation but before parent `fsync`; temporary creation, a flushed partial write, and the full write before file `fsync`; immediately before rename, immediately after rename, and after rename before directory `fsync`. A narrow Linux/arm64 smoke exercises the production syscall helper without claiming full Linux integration. The recursive audit and no-create coordinator detect missing/corrupt committed bytes, inventory orphan entries, and classify storage without initialization. Explicit local-fixture, runner-exception, and pre-dispatch budget-refusal terminalization acquire a cooperative shared maintenance lease before their fresh audit, validate the full ledger/CAS graph before mutation and again at final pre-commit, and capture the returned terminal stream inside the transaction; SQLite writer failures become stable denials. Fixture publication holds shared mode across CAS publication and SQLite binding, and exclusive mode blocks it nonblockingly. Shared recovery is not quiescent against another shared publisher: its narrower action remains guarded by the SQLite writer lock and complete ledger/reachable-CAS revalidation. Explicit quarantine instead holds exclusive mode across a fresh top-level audit, deterministic BEFORE/PLAN/ACTIVE evidence, descriptor-relative no-replace candidate moves, receipts, a clean final audit, AFTER/COMPLETE publication, and durable fence removal. It moves only the complete allowlisted set of ownerless valid-finalized, corrupt-finalized, or temporary regular files; restart reconciles exactly-one-source-or-destination states and otherwise retains the fence. Its local 16-prefix spawned-process `SIGKILL` and six-case cooperating-process matrix now passes with independent audit bindings, fresh-process completion, and identity-preserving idempotency. Later budget errors receive conservative general recovery, and successful evaluation completion also captures its result transactionally. `replay` and `report` inspect existing storage without creating it. Real-process CAS publisher contention, hostile same-UID and broader open-process concurrency stress, real-provider idempotency, reference-host repetition, and the 99% reliability campaign remain incomplete.

## 2. Evidence vocabulary

This report uses the following terms narrowly:

- **Implemented:** code exists for the stated behavior.
- **Contract-tested:** tests inspect or exercise the command, configuration, state transition, or parser behavior. This does not prove host-level containment.
- **Development-smoked:** the behavior ran on the non-reference Docker Desktop environment recorded below.
- **Reference-verified:** the behavior passed on a dedicated rootless x86_64 Linux host with the required controls enabled.

Only **reference-verified** evidence can satisfy the hostile-code portions of the Stage 1 exit gate. A configured Docker flag is not proof that the host kernel or daemon enforced the intended boundary.

## 6. Known limitations and residual risks

- **Rootful development daemon:** Docker Desktop does not establish the required rootless-daemon boundary.
- **Architecture mismatch:** the available ARM VM is not the native x86_64 reference environment. Emulation or a cross-platform build cannot substitute for a native gate run.
- **Shared kernel:** worker and evaluator containers share the Docker VM kernel. Containers reduce exposure but do not defend against every kernel exploit; authoritative runs require a dedicated disposable host without unrelated secrets.
- **Narrow evaluator protocol:** evaluator v2 removes the known shared-interpreter/grader mount from the JSON-callable fixture, but it is not a general pytest, filesystem, service, or arbitrary-command evaluator. New adapters must preserve the disjoint candidate/scorer trust zones.
- **Protocol sizing:** the `python-call-v1` loader has absolute case/depth limits, but its case ceiling is not yet derived from each fixture's output cap. Until that relation is validated, v1 remains restricted to small micro-fixtures.
- **Patch identity ordering:** unsafe shapes are rejected before Git application, and an exact patch-identity mismatch is rejected before sandbox dispatch. The identity comparison currently occurs after validated bytes are applied to a disposable temporary copy, so it is not yet a pre-application identity check.
- **Dynamic input visibility and oracle queries:** candidate code necessarily sees the function inputs in its challenge. Batch invocation also exposes the complete case input set, and repeated pass/fail evaluation can leak information; sealed split access and attempt limits remain required.
- **Two-phase aggregate accounting:** invoke and score currently each receive the declared per-phase Docker limits. Their observed CPU and wall use are not yet reconciled into one evaluation-wide budget.
- **Writable-disk reference evidence:** Docker Desktop repeatedly enforced exact tmpfs byte ceilings with `ENOSPC`; that development result cannot establish quota behavior on the rootless reference host or substitute for an evaluator-level disk outcome.
- **Contract versus enforcement:** command construction can request network, capability, mount, and cgroup restrictions without proving that the daemon honored them.
- **Ambient image environment:** the current pinned image's exact effective candidate/scorer environment names and value hashes are now allowlisted and actively observed. A base-image or runtime change requires a reviewed contract/hash update and new evidence; this does not generalize to future images automatically.
- **Evaluator-only containment profiles:** the active suite mirrors `ContainerEvaluator` candidate/scorer requests and has an always-running drift test. Guildmind does not yet have a general worker dispatcher, so the reports are not worker-sandbox evidence.
- **Evidence authentication:** strict models re-derive checks and prevent partial serialized promotion, but the reports are content-hashed self-consistent evidence, not signed attestations. Trusted CI/build identity or signatures remain future work.
- **Docker endpoint and orphan lifecycle:** strict admission inspects the selected daemon but does not yet prove that the endpoint is the intended local controlled host. Normal cleanup and collision-free randomized operational names are implemented, but an ambiguous `docker create` or control-plane crash can still leave a labeled stopped container; startup discovery/cleanup by managed labels is not implemented.
- **Oracle commitments and feedback access:** current evidence contains unkeyed oracle/task commitments. Low-entropy expected vectors may be vulnerable to offline guessing if those commitments are exposed to adaptive search. The optimizer-facing result projection, keyed or access-controlled commitments, and attempt policy must be fixed before search begins.
- **Crash semantics are local:** the state machine represents an accepted-but-uncommitted request as ambiguous and charges its full reservation, but no real provider adapter has demonstrated idempotency, status polling, duplicate suppression, or invoice reconciliation.
- **Bounded process-crash injection:** eleven development cases send real `SIGKILL` after five committed EventStore phases, after SQL execution but before four selected commits, and while FixtureRunner is inside model or evaluator work. Nine Darwin CAS cases cover hierarchy creation, empty/partial/full temporary writes, file `fsync` plus verification, atomic rename, and final directory sync; killed temporaries remain exact evidence across two retries. Quarantine adds all 16 predeclared record/move/receipt/completion/unfencing prefixes plus six cooperating-process publisher/maintainer/resumer cases; every prefix is independently audited and completes or returns a post-completion no-op in fresh processes. Power loss, real-process CAS publisher contention, hostile same-UID races, and broader concurrent commit races remain untested. Provider idempotency and polling are also untested.
- **CAS verification and orphan lifecycle:** the pre-commit tests inventory exactly one patch orphan and three evaluation orphans and prove recovery does not bind them. Explicit local-fixture recovery holds shared maintenance mode across its fresh read-only audit and repeats direct/typed-recursive byte verification under the writer window. Explicit quarantine now holds exclusive mode and preserves only the three freshly authorized ownerless regular-file classes through immutable plans, no-replace moves, receipts, and forward reconciliation. Direct low-level callers remain trusted, an actively hostile same-UID process can ignore or race the lease, and there is still no automatic startup sweep, deletion, or garbage collection.
- **Incomplete resource accounting:** the integrated ledger durably reserves/reconciles model usage and enforces one call for the current lifecycle, but observed evaluator/container wall and CPU consumption is not yet reconciled into `BudgetUsage`.
- **Probe is not a gate:** `doctor --production` is a necessary host/image/control probe. Even a passing probe would not certify evaluator discrimination, complete transaction/CAS crash recovery, corpus hygiene, or the 99% reliability campaign.
- **Fixture breadth and reliability:** the repository does not yet contain the planned 20 known-outcome fixtures, and the predeclared 99% normal-fixture campaign has not run.
- **No authorization expansion:** external repositories, arbitrary model-generated commands, real provider calls, baseline campaigns, institution genomes, search, PettingZoo, persistent memory, and judge societies remain unauthorized by this checkpoint.

## 7. Reference-host gate procedure

The known shared-interpreter false pass is closed for `python-call-v1`; this development result does not substitute for the following procedure on a dedicated disposable x86_64 Linux host with no unrelated credentials or valuable data:

1. Install and select a rootless Docker daemon. Prove the Docker endpoint is the intended controlled host, and record OS, kernel, native architecture, client/server versions, storage driver, seccomp profile, and daemon security options.
2. Confirm cgroup v2 delegation for the rootless user and prove CPU, memory, PID, and wall-time enforcement. Provision and prove a real writable-byte quota.
3. Check out the reviewed checkpoint by commit hash. Build or pull the evaluator for native `linux/amd64`; record the Dockerfile hash, pinned base digest, resulting immutable image digest, and any registry provenance.
4. Run `guildmind doctor --production --json` with the exact evaluator repository digest and require a fail-closed result if any mandatory control is unavailable. Preserve its machine-readable output; do not treat a pass as the Stage 1 verdict.
5. Run formatting, lint, type, unit, integration, replay, and 100-repetition semantic-determinism checks from the locked environment.
6. Run every adversarial sandbox/evaluator case in the matrix above. Preserve container inspect data, cgroup readings, stdout/stderr artifacts, structured outcomes, and cleanup evidence.
7. Repeat the committed-prefix, selected pre-`COMMIT`, runner external-work, complete nine-prefix CAS-publication, and 16-prefix quarantine `SIGKILL` matrices. Repeat the quarantine publisher/resumer concurrency matrix, add deterministic real-process CAS publisher contention, and preserve power-loss/fault evidence as a separate durability claim.
8. Run the predeclared normal-fixture reliability campaign. Reconcile every intended attempt to exactly one terminal manifest; report infrastructure failures with the denominator. The rate must be at most 1%.
9. Re-evaluate with the exact recorded image digest. Rebuild the pinned definition separately and label any comparison as supply-chain validation, not execution identity.
10. Review every failure without waiving a critical control. Update this report with immutable evidence references and retain **NOT PASSED** unless every Stage 1 exit criterion is satisfied.
